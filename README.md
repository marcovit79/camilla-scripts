# Camilla Scripts

Data processing and analytics tools for transforming and validating **Mexal** ERP exports using **Apache Spark SQL**.

The repository provides two environments for executing parameterized Spark SQL pipelines:
1. **`analitic_job/`**: A containerized **PySpark** runner (via Podman) for automated batch execution and CSV export.
2. **`rProject/`**: An **RStudio / `sparklyr`** project for interactive SQL development, debugging, and data exploration.

## SQL File Format

SQL scripts in `analitic_job/sql/` use a custom multi-statement format designed for both the Python and R runners:
- **Statement Delimiters**: Individual SQL statements are separated by lines starting with `===` (e.g., `=== Read alias`), which act as section headers/comments.
- **Variable Placeholders**: Dynamic values and file paths use `${VAR_NAME}` syntax (e.g., `LOCATION 'file://${ALIAS_CSV_PATH}'`), which are substituted prior to execution.

### Current SQL Pipelines
- **`compute_foglio_articoli.sql`**: Loads raw Mexal CSV exports (`alias.csv`, `articoli_1.csv`, `articoli_5.csv`, `fornitori.csv` with `ISO-8859-1` encoding and `;` delimiter) into external Spark tables and creates the `foglio_articoli` temporary view with computed fields (unit conversions, VAT, price per kg/lt, and markup/ricarico).
- **`check_foglio_articoli.sql`**: Loads a reference Google Drive export (`foglio_articoli_da_drive_*.csv`) and creates the `foglio_articoli_diffs` temporary view comparing the computed `foglio_articoli` view against the Drive sheet to highlight mismatches or missing records.

## Usage

### 1. Containerized Batch Execution (`analitic_job`)

#### Prerequisites
- [Podman](https://podman.io/) installed on the host machine.
- Input CSV files placed in `analitic_job/mexal_exports/` (or your chosen input directory):
  - `alias.csv`
  - `articoli_1.csv`
  - `articoli_5.csv`
  - `fornitori.csv`
  - `foglio_articoli_da_drive_2026_03_01.csv` (for validation)

#### Running the Pipeline
Run the batch script directly (Pass `--do-checks` to also execute `check_foglio_articoli.sql`):
```bash
cd analitic_job
./generate-foglio_articoli.sh              # Generate foglio_articoli.csv only
./generate-foglio_articoli.sh --do-checks  # Generate and run comparison checks
```

Or build the container image and invoke `execute_sql_file.sh` manually:
```bash
cd analitic_job
podman build -t spark-sql-runner .

./execute_sql_file.sh \
  "--sql-file=./sql/compute_foglio_articoli.sql" \
  "--subst-ALIAS_CSV_PATH=./mexal_exports/alias.csv" \
  "--subst-ARTICOLI_1_CSV_PATH=./mexal_exports/articoli_1.csv" \
  "--subst-ARTICOLI_5_CSV_PATH=./mexal_exports/articoli_5.csv" \
  "--subst-FORNITORI_CSV_PATH=./mexal_exports/fornitori.csv" \
  "--export-foglio_articoli=./results/foglio_articoli.csv"
```

#### CLI Arguments (`execute_sql_file.sh` / `run_spark_sql.py`)
| Argument | Description |
| :--- | :--- |
| `--sql-file=<path>` | Path to a `.sql` file to execute. Can be specified multiple times; files are executed in order within the same Spark session. |
| `--subst-<KEY>=<VAL>` | Replaces `${KEY}` in the SQL files with `<VAL>`. When using `execute_sql_file.sh`, any key ending in `PATH` automatically stages the host file into the container's isolated input volume. |
| `--export-<TABLE>=<DEST>` | Exports the Spark table or view `<TABLE>` to `<DEST>` as a `;`-delimited CSV file after all SQL files have been executed. |

> **Note on `generate-foglio_articoli.sh`**: Double-check the `MEXAL_EXPORT_DIR` and `BASE_MEXAL_EXPORT_DIR` directory variables before running to ensure they point to your export directory (e.g. `mexal_exports`).

### 2. Interactive Execution in R (`rProject`)

#### Prerequisites
- **R** and **RStudio**
- R packages: `sparklyr`, `dplyr`, `DBI`
- A local Spark installation managed via `sparklyr` (e.g., `sparklyr::spark_install()`)

#### Running Interactively
1. Open `rProject/rProject.Rproj` in RStudio.
2. Ensure the `mexal_exports` directory contains the required CSV files.
3. Run `executeSqlFile.R` to connect to a local Spark instance, execute the SQL scripts, and query the resulting views (`foglio_articoli`, `foglio_articoli_diffs`) directly into R data frames.
